## 本地维护的软件

ComfyUI 不再由本仓库安装，不提供启动器、Python/CUDA 环境或专用缓存。
如有需要，按 ComfyUI 官方说明在仓库外单独安装，并记录其源码、Python 和 PyTorch/CUDA 版本。
NixOS 上普通 Python 虚拟环境不保证能直接运行预编译 CUDA wheel，需按实际情况选择独立项目环境或容器；不为此扩大全局 nix-ld 库列表。

- 切换新配置后，Home Manager 将不再管理旧 `~/.local/bin/comfyui` 入口；确认激活成功再创建本地入口。
- 原数据目录 `~/.local/share/comfyui`（或原 `XDG_DATA_HOME` 下对应目录）的模型、插件及用户 Python 包不会被本次变更删除。安装前先备份，按新版本兼容性选择性复用。
- 本地软件及数据不随 Nix 配置更新，也不随 NixOS 代际回滚；旧系统代际仍可能保留原声明式启动器。

## 配置所有权与工具保留

- Nix 客户端、fontconfig、QQ flags、btop、Topgrade 和 Fcitx5 的声明式文件均归 HM 管理，不再使用 `force = true`。GUI 中对这些文件的修改应回写对应模块；不要重新添加强制覆盖来掩盖竞争。
- 2026-10-27 只读核验：上述 7 个文件均为符号链接。普通文件冲突使用已有 `.hm-bak` 备份策略；如备份已存在而激活停止，先核对差异、备份数据，再人工处理，禁止批量删除备份或用户文件。
- 保留原有 Nix 生态工具；此前移入 devShell 的 `nix-update`、`nixdoc`、`nix-init`、`flake-checker`、`nix-melt`、`nix-health`、`nixos-anywhere` 已恢复至 `modules/nix.nix`，其余工具保持原有作用域。
- 缓存移除无对应输入的 nix-gaming，以及旧 pre-commit-hooks 入口和公钥；保留当前 git-hooks 缓存。其余与现有组件相关的缓存暂不盲删。

## nix-ld 与恢复验证边界

- `modules/nix-compat.nix` 的库按基础、GUI、显示、音视频及网络/运行时分组，但尚无经运行验证的逐程序依赖清单。本轮不把分组注释当作消费者证明，也不裁剪未知依赖。
- 后续按实际外部程序记录「程序/版本 → 缺少的库 → 启动与功能验证」，只在确认无消费者后删库；独有依赖优先迁入程序自己的 wrapper 或仓库外项目环境。
- 2026-10-27 只读核验：系统有 4 个代际链接；系统及用户侧 secrets 私钥文件存在、权限均为 `0600`，未读取内容。**不代表旧代可启动、密钥可解密或外部备份可恢复。**
- 仓库未声明 Restic/Borg 备份任务；外部介质位置与已有备份状态未知，不自动创建备份仓库、复制私钥、重启或执行系统回滚。

恢复演练仍待现场确认，按顺序完成并记录日期及结果：

1. 确认启动菜单有已知可用的旧代，在允许重启时实际启动并核验登录、网络和秘密激活。
2. 核对外部安全介质上的私钥副本；在安全环境验证解密，不把密钥内容或解密结果写进 Git/Store。
3. 从独立备份恢复一份非敏感样本到新建空目录，核对内容或校验和，不覆盖工作文件；快照不计作独立备份。
4. 确认 Documents、代码、忽略的媒体及本地 ComfyUI 数据都有明确备份位置和恢复方式。
