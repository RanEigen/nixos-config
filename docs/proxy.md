# 本机代理与 fcclient 移除流程

## 所有权

配置仅从 `hosts/omen/proxy/default.nix` 接入，其他主机不受影响。

| 文件 | 负责内容 |
|---|---|
| `settings.nix` | 后端地址、端口和 dae 接口 |
| `dae.nix` | 透明转发、DNS、直连规则合并、接口防火墙和地址服务 |
| `clash.nix` | Clash 安装、托盘项、核心进程直连 |
| `fcclient.nix` | 私有客户端的进程直连、托盘项、`fcproxy_port` 会话变量 |

本仓不安装 fcclient，不管理它的订阅、账户或仓库外私有 flake，也不为它增加 root/TUN 权限。

## 使用两个客户端

- 两个客户端均保留，**不代表同时启动两个后端或自动切换**。
- dae 使用 `settings.nix` 定义的固定 SOCKS 后端。客户端监听参数由 GUI 管理，必须与这里一致。
- 使用同一端口时，只启动一个监听者；切换前关闭原监听，再配置并启动另一个客户端。
- dae 的后端请求来自网络命名空间，不能只监听宿主机 loopback；现有接口防火墙只允许 dae 接口访问后端端口，不向局域网放行。
- 两个客户端的核心进程均有直连例外，避免后端流量再次进入 dae。
- 后端不可达时，国内直连规则仍在，其他流量失败；不会悄悄退回直接联网。

## 移除 fcclient

1. 删除 `hosts/omen/proxy/default.nix` 中 `./fcclient.nix` 的导入。
2. 执行 `nix flake check` 和完整主机构建；仓库已提供 `proxy-without-fcclient` 组合求值检查。
3. 确认 Clash 已按同一后端设置工作，再切换系统、退出并重新登录会话。
4. 核验生成的 dae 配置不再包含私有进程规则，托盘不再固定该项，新 shell 不再继承 `fcproxy_port`。
5. 对仓库外安装单独清理：先检查 `nix profile list`、用户服务、桌面启动项与安装来源，再按实际来源卸载。不要盲删整个用户配置目录。
6. 如 fish 曾保存通用变量，检查 `set --show fcproxy_port`，必要时用 `set --erase --universal fcproxy_port` 清理。运行中的旧进程环境要通过重启会话更新。
7. Noctalia 的 GUI 覆盖层可能仍保存私有托盘固定项；在 GUI 中取消固定，或按其安全流程移除对应覆盖键。

本仓不自动停止客户端、删除订阅/凭据或清理 Store。旧代际和 GC roots 会继续保留旧闭包；确认新配置稳定后再按保留策略清理，不能为“无痕”牺牲回滚能力。

若以后完全不需要透明代理，移除主机入口的整个 `./proxy` 导入，并在切换后核验 dae 服务、转发参数及接口防火墙。这里只解除声明式接线，不代替运行时验收。
